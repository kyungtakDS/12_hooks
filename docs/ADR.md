### ADR-004: 커밋 전 리뷰 훅을 `type:"agent"` 가 아니라 `type:"command"` 로 구현
**상태**: Accepted (2026-07-25)
**결정**: 커밋 직전 코드 리뷰를 Claude Code 의 `type:"agent"` 훅 대신 `type:"command"` 훅으로 구현한다.
**이유**: `~/.claude/settings.json` 에 `type:"agent"` + `if:"Bash(git commit*)"` 로 등록했으나 한 번도 발동하지 않았다.
운영 자격증명이 담긴 파일을 스테이징하고 `git commit` 을 실행해도 리뷰·차단 없이 즉시 통과했다(2회 재현).
스키마는 공식 문서상 유효했고 Claude Code 2.1.219 로 버전 문제도 아니었다. 근본 원인은 특정하지 못했다.
반면 `type:"command"` 훅은 같은 저장소에서 실제 차단이 확인된다.
**트레이드오프**: 셸 스크립트라 프롬프트·파싱을 직접 관리해야 한다. 대신 동작이 검증 가능하다.
**참고**: 이 결정은 이전의 `agent` 훅 방식을 대체하지만, 그 방식은 ADR 로 기록된 적이 없어
Superseded 로 표시할 대상이 없다.

### ADR-005: `claude -p` 프롬프트를 argv 가 아니라 stdin 으로 전달
**상태**: Accepted (2026-07-25)
**결정**: 훅에서 `claude -p "$PROMPT"` 대신 `printf '%s' "$PROMPT" | claude -p` 를 쓴다.
**이유**: 실측 — 33,038자 프롬프트를 인자로 넘기자 `exit 126: Argument list too long` 으로 죽었다.
Windows 명령줄 한도는 32,767자다. diff 가 클수록 확실히 걸려서, **정작 검사가 가장 필요한 큰 변경에서
검사가 통째로 빠졌다.** 같은 프롬프트를 stdin 으로 넘기니 5초에 정상 처리됐다.
**트레이드오프**: 없음.

### ADR-006: 훅 리뷰 모델로 `claude-haiku-4-5` 를 쓴다
**상태**: Accepted (2026-07-25)
**결정**: `precommit-review.sh` 와 `.githooks/pre-push` 의 기본 모델을 haiku 로 하고,
환경변수(`PREPUSH_REVIEW_MODEL` 등)로 교체 가능하게 둔다.
**이유**: 같은 44KB diff 실측 — `claude-sonnet-5` 는 180초 안에 끝내지 못해 검사가 생략됐고,
`claude-haiku-4-5` 는 78초에 완료했다. 민감도도 확인했다: 30KB diff 끝에 묻어둔
AWS·Stripe 키를 haiku 가 43초에 잡아냈다.
**트레이드오프**: 미묘한 로직 버그 검출력은 sonnet 이 낫다. 그러나 push 를 몇 분씩 붙잡는 훅은
결국 `--no-verify` 로 상시 우회되어 0 이 된다. 실제로 도는 검사가 이론상 더 나은 검사보다 낫다.

### ADR-007: 훅은 fail-open, CI 는 fail-closed
**상태**: Accepted (2026-07-25)
**결정**: 로컬 훅은 리뷰 실패 시 통과시키되 이유를 반드시 출력한다.
CI(PR 리뷰)는 리뷰 실패 시 PR 댓글과 로그에 원인을 남기고 job 을 실패시킨다.
**이유**: 로컬에서 훅 오류로 작업이 막히면 훅 자체가 꺼진다. 반대로 CI 가 조용히 통과하면
검사가 있으나 마나다. 방향이 반대여야 각자의 목적을 달성한다.
**트레이드오프**: 로컬은 검사가 빠진 채 커밋될 수 있다. 그래서 "조용히" 넘어가지 않는 것이
이 결정의 핵심이다 — 건너뛴 이유를 반드시 출력한다.

### ADR-008: PR 리뷰 댓글은 마커로 찾아 갱신한다
**상태**: Accepted (2026-07-25)
**결정**: 댓글 본문에 `<!-- gpt-pr-review -->` 마커를 심고, 재실행 시 마커가 든 기존 댓글을 찾아
갱신한다. 없을 때만 새로 단다. 여러 개면 가장 오래된 것을 갱신한다.
**이유**: 처음에는 `gh pr comment --edit-last` 를 썼으나, 이는 봇의 **마지막** 댓글을 무조건
편집하므로 무관한 댓글을 덮어쓸 수 있다. 마커 방식은 대상이 명확하고 멱등이다.
3회 실행에도 댓글이 1개로 유지됨을 확인했다.
**트레이드오프**: 댓글 목록 조회 API 호출이 한 번 더 필요하다.

### ADR-009: Risk Score 의 총점과 등급은 모델이 아니라 도구가 계산한다
**상태**: Accepted (2026-07-25)
**결정**: 모델은 항목별 점수와 근거만 JSON 으로 내고, 합계·등급·정규화는 `pr_review.py` 가 한다.
근거(`evidence`)가 비어 있으면 그 항목을 0점으로 내린다.
**이유**: 모델이 근거와 어긋나는 점수를 준다. 실제로 "광범위한 신규 테스트 추가"(위험을 줄이는 일)에
15점 만점 중 10점, "API 키를 Secrets 로 관리"(올바른 처리)에 30점 만점 중 5점을 매겼고,
발견된 문제는 0건인데 총점이 25 로 나왔다. 만점 초과·음수·비숫자 값도 실제로 방어가 필요하다.
**트레이드오프**: 없음. 산수를 코드가 하는 편이 항상 낫다.

### ADR-010: 런타임 외부 의존성을 두지 않는다
**상태**: Accepted (2026-07-25)
**결정**: `scripts/*.py` 는 표준 라이브러리만 쓴다. 훅 셸 스크립트는 셸 내장과 coreutils 만 쓴다.
개발 의존성은 pytest 하나로 제한한다.
**이유**: CI 에 `pip install` 단계를 두지 않기 위해서다(테스트 워크플로의 pytest 설치는 예외).
훅은 jq 같은 도구가 없는 환경에서도 돌아야 한다.
**트레이드오프**: JSON 파싱을 셸에서 직접 해야 해서 훅 스크립트가 길어진다.
`bash-guard.sh` 와 `precommit-review.sh` 는 정확한 파싱 대신 페이로드 전체를 grep 하는 쪽을 택했다.
